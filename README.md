# 가족 공동 별장 예약 관리 서비스

가족 및 외가 친척이 공동으로 사용하는 별장을 대상으로,  
**예약 / 조회 / 취소 / 승인 관리**가 가능한 **폐쇄형 예약 관리 서비스**를 만드는 프로젝트입니다.

이 프로젝트는 단순 CRUD가 아니라,  
**초대코드 기반 가입 / 관리자 승인 / JWT 인증 / 날짜 단위 예약 정책**까지 포함한  
실전형 백엔드 포트폴리오 프로젝트를 목표로 개발 중입니다.

---

## 1. 프로젝트 소개

기존의 가족 단위 별장 사용 방식은 보통 카카오톡, 전화, 구두 조율에 의존하는 경우가 많아  
아래와 같은 문제가 발생할 수 있습니다.

- 누가 언제 쓰는지 한눈에 보기 어려움
- 일정이 겹쳤을 때 기준이 불명확함
- 가족 외 지인이 무단 접근할 수 있음
- 관리자가 가입/이용을 통제하기 어려움

이 프로젝트는 이런 문제를 해결하기 위해 다음을 핵심 방향으로 설계했습니다.

- **폐쇄형 서비스**
- **1회용 초대코드 기반 회원가입**
- **관리자 승인 후 사용 가능**
- **날짜 단위 예약 시스템**
- **캘린더 기반 예약 조회**
- **가족 단위 운영에 맞는 단순하고 명확한 UX**

---

## 2. 핵심 기능

### 인증 / 사용자

- 1회용 초대코드 기반 회원가입
- 가입 시 본인 식별용 메모(`signupNote`) 선택 입력
- 가입 직후 `PENDING` 상태 저장
- 관리자 승인 후 `ACTIVE` 상태에서만 로그인 가능
- JWT 기반 로그인 인증

### 초대코드

- 초대코드 생성 / 사용 / 만료 / 폐기 상태 관리
- 초대코드 상태값:
  - `ACTIVE`
  - `USED`
  - `EXPIRED`
  - `REVOKED`
- 만료된 초대코드는 사용 시 자동 `EXPIRED` 처리

### 예약 (구현 예정 포함)

- 날짜 단위 예약
- 하루 예약 허용
- 시작일 ~ 종료일 포함
- 월별 캘린더 조회
- 예약 취소
- 관리자 예약 수정

## 3. 핵심 정책

### 회원가입 정책

- 아무나 회원가입 불가
- 반드시 **1회용 초대코드** 필요
- 가입 시 `signupNote`는 **선택 입력**
- 가입 후 바로 서비스 이용 불가
- **관리자 승인 후 ACTIVE 상태**가 되어야 로그인 가능

### 로그인 정책

- `ACTIVE` 사용자만 로그인 가능
- `PENDING`, `REJECTED` 계정은 로그인 차단
- 아이디 존재 여부 / 비밀번호 오류 여부는 과도하게 구분하지 않음

### 예약 중복 정책

날짜 겹침 판정 기준은 아래와 같습니다.

```text
기존 예약: A ~ B
신규 예약: X ~ Y

중복 조건:
A <= Y && B >= X
```

즉, 날짜가 하루라도 겹치면 중복 예약으로 간주합니다.

## 6. 현재 구현 완료 범위

- `POST /auth/signup`
- loginId 중복 검사

- 초대코드 상태 검사

- 비밀번호 BCrypt 해시 저장

- `POST /auth/login`
- loginId 조회
- 비밀번호 검증
- `ACTIVE` 상태만 로그인 허용
- JWT access token 발급

### JWT 인증 기반

- JWT 생성
- JWT 유효성 검증
- JWT에서 userId / loginId / role 추출
- JWT 인증 필터 구성
- Spring Security에 JWT 필터 연결
- Stateless 인증 구조 적용

## 7. 검증 완료 항목

### 회원가입 검증

- 정상 회원가입 성공
- 중복 loginId 차단
- 존재하지 않는 초대코드 차단
- 이미 사용한 초대코드 차단
- 만료된 초대코드 차단
- `signupNote` 미입력 회원가입 허용

### 로그인 검증

- `PENDING` 계정 로그인 차단
- `ACTIVE` 계정 로그인 성공
- 잘못된 비밀번호 로그인 실패
- 존재하지 않는 아이디 로그인 실패

## 8. 트러블슈팅 / 개선 포인트

### 1) 만료된 초대코드가 DB에 ACTIVE로 남는 문제

#### 문제

만료된 초대코드로 회원가입 시도 시,  
회원가입은 실패했지만 DB 상 초대코드 상태가 `ACTIVE`로 남아 있는 문제가 있었습니다.

즉 실제로는 사용할 수 없는 코드인데,  
관리자 입장에서는 살아있는 코드처럼 보이는 상태 불일치가 발생했습니다.

#### 원인

같은 트랜잭션 안에서:

- 초대코드 상태를 `EXPIRED`로 변경하고
- 바로 예외를 던지는 구조

로 작성했기 때문에,  
예외 발생 시 전체 트랜잭션이 롤백되면서 상태 변경도 같이 취소되었습니다.

#### 해결

`InviteCodeService`를 별도 분리하고,  
`REQUIRES_NEW` 트랜잭션으로 만료 처리만 따로 커밋하도록 수정했습니다.

#### 결과

- 회원가입은 실패
- 초대코드는 실제 DB에서 `EXPIRED`로 반영

즉 **비즈니스 검증과 상태 정합성**을 동시에 맞췄습니다.

---

### 2) VSCode PowerShell 한글 깨짐 문제

#### 문제

개발 중 VSCode PowerShell 터미널에서
한글 로그 / 예외 메시지가 깨지는 문제가 발생했습니다.

#### 해결

- 터미널 UTF-8 코드페이지 적용
- PowerShell Input / Output Encoding 설정
- Gradle JVM UTF-8 설정
- JavaCompile UTF-8 설정
- PowerShell 프로필 자동 적용

#### 결과

개발 중 한글 로그/예외 메시지가 안정적으로 출력되도록 환경을 정리했습니다.

## 10. 보안 / 설정 관리

이 프로젝트는 GitHub 업로드 및 이후 배포를 고려하여  
민감한 설정값은 **환경변수(.env 또는 외부 설정)** 로 분리하는 방향으로 관리할 예정입니다.

예시 대상:

- DB 접속 정보
- JWT Secret Key
- 배포 환경 설정값

즉, 실제 운영/배포에 필요한 민감 정보는  
소스코드에 직접 하드코딩하지 않고 분리 관리하는 방향으로 정리할 예정입니다.
